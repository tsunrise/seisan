# Privacy claim-to-code map

## Purpose and authority

`privacy_policy.md` is Seisan's public source of truth. This document is an internal traceability map: it connects each material public claim to the implementation, configuration, documentation, or operating practice that supports it. It is not itself a public privacy notice or a substitute for legal review.

Evidence types used below:

- **Code-enforced:** application code or a schema directly implements the claim.
- **Configuration-dependent:** the behavior depends on deployed Cloudflare bindings, settings, or provider terms as well as repository code.
- **Operational assertion:** the claim depends on controller identity, legal analysis, or a human operating process that the repository cannot enforce.
- **Repo-wide negative claim:** confidence requires auditing dependencies and all browser/server network paths; one citation cannot prove the absence of a behavior.

## Maintenance checklist

Read this document before changing any of the following, then update every affected row in the same change:

- Data fields, schemas, free-text inputs, derived values, exports, or administrative views.
- Project access rules, public/restricted visibility, membership, ownership, or authorization.
- Login, sessions, API keys, Turnstile, abuse controls, DNS validation, or email delivery.
- Browser cookies, `localStorage`, `sessionStorage`, caches, offline storage, or service workers.
- External requests, third-party scripts, Cloudflare bindings, service providers, or subprocessors.
- Workers AI, embeddings, Vectorize, automated suggestions, scoring, or user overrides.
- Application/platform logging, observability, rate-limit state, security telemetry, or error reporting.
- Expiration, cleanup, deletion, tombstones, archival, backups, or provider retention settings.
- Geographic processing, transfer mechanisms, controller/representative facts, or legal applicability.
- Privacy-request tools, consent/opt-out controls, Global Privacy Control, age handling, or other user rights.
- Dependencies or network behavior that could invalidate a repo-wide negative claim. A statement such as “no analytics SDKs” requires a dependency, source, built-output, and runtime network audit, not one code citation.

## Privacy release checklist

1. Update affected claim-map rows and evidence symbols.
2. If public behavior or a public claim changed, update `privacy_policy.md`; use a new effective or last-updated date for substantive changes.
3. Run `node scripts/build-privacy-policy.mjs` to regenerate `public/privacy_policy.html` and confirm generated table-of-contents anchors match the policy headings.
4. Verify `/privacy`, `/privacy_policy.html`, contact links, provider links, and any contextual deep links.
5. Run `pnpm run test:privacy`, the narrowest relevant typecheck/tests, `pnpm run lint`, `pnpm run format:check`, and `pnpm run build` before handoff.
6. Browser-check desktop, tablet, and 390px mobile layouts, keyboard focus, skip navigation, loading/error states, and horizontal overflow.
